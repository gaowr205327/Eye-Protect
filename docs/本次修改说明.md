## 一、这个软件是干什么的

**护眼助手**是一款跑在 Windows 10/11 上的桌面小工具（单个 exe，双击即用、无需安装）。
**完全离线运行，不联网、不收集任何数据。**

它只做两件事：

| 功能 | 说明 |
|---|---|
| **定时休息提醒** | 每隔你设定的时间（默认 45 分钟），在屏幕上弹出提醒窗口，提示你远眺、眨眼、起身活动。弹窗文案可自定义多条，轮流或随机展示 |
| **每日打卡提醒** | 一天 4 次（上班 / 午休 / 午休结束 / 下班），到点弹窗提醒打卡。每条的开关、时间、提示词都独立可改 |

几个特点：

- **托盘常驻**：点关闭按钮只是缩到托盘，程序继续在后台提醒；托盘右键可"立即提醒 / 退出"
- **不抢焦点**：弹窗只置顶显示，绝不抢走你正在打字的光标
- **界面**：星露谷田园像素风，木头招牌、木质卡片、草地装饰条，配像素中文字体（Fusion Pixel，OFL 开源授权，只对本程序生效，不装进系统）
- **三个标签页**：主功能（提醒间隔 / 提醒文案）、打卡提醒（4 条打卡）、设置（弹窗、提示音、开机自启、按钮文案）
- **配置存放**：`%APPDATA%\EyeReminder\config.json`，改哪存哪、即时生效

## 二、这次改了什么

### ① Bug 修复：主功能页「快捷设置」的绿色高亮一直是固定的

**原来的毛病**：`20分 / 25分 / 45分 / 60分` 四个快捷按钮，绿色（选中态）是在**界面第一次画出来时**算好的，之后再也不会变。所以你点「60分」，数字确实是 60，但绿色还赖在 25 分上；反过来也一样。

**改法**：按钮只建一次，但高亮交给一个专门的刷新函数，**每次间隔值一变就重算** —— 命中的那个变绿，其余的恢复浅木色。

**现在的表现**：

- 点哪个，哪个变绿（点「45分」→ 45 分变绿，其余取消）
- 用数字框直接输入非快捷值（如 37 分钟）→ 四个按钮**全不亮**，不会有一个假的"选中"
- 启动时按配置里的真实值点亮（配置是 60 就亮 60，不再是硬编码的某个）

---

### ② 新增：弹窗「稍后提醒」（第二个按钮）

**原来的毛病**：弹窗只有一个「知道了」，点掉就结束了，错过也没办法 —— 比如你正专注写代码，弹窗一闪而过就没下文了。

**改法**：休息弹窗的按钮变成两个：

```
┌──────────────────────────────────────┐
│  （木牌外观 + 标题「该休息啦」）        │
│                                      │
│         眼睛累了，看看远处 20 秒吧～   │
│                                      │
│  ┌ 知道了，继续干活 ┐ ┌ 稍后 5 分钟 ┐  │
│  │    （草地绿）    │ │  （浅木色）  │  │
│  └─────────────────┘ └─────────────┘  │
│         下次提醒 45 分钟后（8s 自动关闭）│
└──────────────────────────────────────┘
```

点「稍后 5 分钟」→ **弹窗关掉，5 分钟后重新提醒**（这次不算数，休息计时从当前时刻重新起算）。

两个按钮的样式有意区分：主按钮是草地绿（最显眼的那个动作），「稍后」是浅木色（次级动作）。

**几点设计说明**：

- **只给休息弹窗加**。打卡提醒是"到点就该做"的事，延后它没有意义，所以打卡弹窗保持单按钮。
- **延后分钟数可改**：设置页可以调（1~60 分钟，默认 5 分钟），按钮文字会跟着变成「稍后 N 分钟」。
- **只生效一次**：延后 5 分钟后再弹时，下一次就恢复成你设定的正常间隔（45 分钟），不会一直 5 分钟循环。
- **实现位置**：调度器新增 `defer(seconds)` —— 写入一个"一次性延后值"并唤醒调度线程重算下一次休息时刻（`_rest_deadline()`），延后值取走即清空。

---

### ③ 新增：一次弹多个弹窗 + 铺在桌面不同位置 + 点任一个全部关闭

**要解决的问题**：单个弹窗容易被挡（别的窗口压着、落在副屏上、你正好没往那边看），一错过就没了。

**改法**：设置页新增「弹窗个数」（1 ~ 6，默认 1）。

- **数量 = 1**：行为和以前**完全一样** —— 屏幕正中央弹一个。（默认值就是 1，不改设置的话你的使用体验不会有任何变化）
- **数量 ≥ 2**：一次提醒同时弹 N 个，铺在桌面的**不同位置**：

| 个数 | 落点 |
|---|---|
| 2 | 左上 + 右下（对角） |
| 3 | 左上 + 正中 + 右下（对角线） |
| 4 | 四个角 |
| 5 | 四个角 + 正中 |
| 6 | 上排三个 + 下排三个 |

- **互不重叠**：落点算完会做一次两两重叠检查；屏幕偏小放不下时，自动回退成"居中网格排布"，同样保证不叠在一起。
- **点一个 = 全关**：不管点的是哪个弹窗、点的是「知道了」还是「稍后」，**同批弹窗一起关闭**。
- **滑入方向**：落在屏幕上半部的从上方滑入，下半部的从下方滑入（不然右下角那个要横穿整个桌面飞下来，很怪）。
- 打卡弹窗同样按设定的个数弹出。

## 三、新增的两个设置项

都在 **设置 → 通用设置** 卡片里：

| 设置项 | 默认 | 范围 | 说明 |
|---|---|---|---|
| 弹窗个数 | 1 | 1 ~ 6 | 单次提醒同时弹出几个（铺在桌面不同位置，点任一个全关） |
| 稍后提醒 | 5 | 1 ~ 60 分钟 | 休息弹窗第二个按钮的延后分钟数 |

超范围的值（比如手工把配置文件改成 99）读取时会自动修正到合法范围，不会异常。

## 六、打包与交付

本次改动**已经重新打包完成**，两个版本任选其一：

| 版本 | 位置 | 大小 | 启动速度 | 适用场景 |
|---|---|---|---|---|
| **单文件版** | `dist\护眼助手.exe` | 21.3 MB | 约 25 秒（每次启动要先自解压） | 拷给别人、放 U 盘，一个文件搞定 |
| **目录版** | `dist\护眼助手\护眼助手.exe` | 整目录 52 MB | 约 2 秒 | 自己长期用，启动快 |

两版功能完全一致。目录版**必须整个文件夹一起拷走**，只拿里面的 exe 会缺依赖无法运行。

### 启动自检

窗口版程序崩溃时不会有任何报错提示，所以打包后对两个产物都做了一次真实启动验证
（利用程序自己的单实例端口握手判断是否进入了主循环）：

| 产物 | 结果 | 实测启动耗时 |
|---|---|---|
| 单文件版 | **通过** | 24.7 秒 |
| 目录版 | **通过** | 2.1 秒 |

验证用的脚本留在 `build\_verify_exe.py`，以后打完包可以直接
`python build\_verify_exe.py <exe路径>` 复用。

### 顺带修掉的一个打包脚本缺陷

`build.bat` 里字体资源用的是相对路径，而这台机器上的 PyInstaller 6.21 会把相对路径
解析到 spec 文件所在目录，导致打包直接报错退出（`Unable to find ...\build\assets\fonts`）。
已改成绝对路径，现在一键打包脚本可以正常跑通。
